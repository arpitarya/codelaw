# Spell checking — the forks

> **Verdict:** decided by the decider, 2026-10-27 · codelaw's own spell checker, not CSpell · a separate `spell` pack on npm and PyPI · the known-typo check on once installed, the dictionary check opt-in · the typo list generated by codelaw from SCOWL · SCOWL, VarCon and CSpell's MIT software-terms list ratified (L11 D-42–D-44) · the word data in the pack, not the engine · confidence high on the licences, medium on how many typos a generated list catches · **reopen-trigger:** the generated list catches under half the typos `typos` finds on the pinned corpus, or upstream `typos` settles its word list's licence as permissive.

## Context

**Arpit, 2026-10-27:** *"There is a tool called C-Spell. Research it and tell me if that can be built into CodeLaw. A similar feature, a better feature, would be even better."*

What the research found: CSpell (MIT, Node) reads code as words — split at `camelCase`/`snake_case`, URLs and hashes skipped — and checks them against compiled dictionaries, some MIT, some LGPL/GPL. It suggests but never fixes unattended, and its users report heavy configuration and slow runs on big repos. `typos` (Rust, MIT/Apache) only flags words on a known-misspelling list and fixes them, with few false positives; its list traces to Wikipedia's share-alike *Lists of common misspellings*, and its licence question (typos #44) is open. codespell is GPL with CC-BY-SA data. Hunspell-compatible engines are MPL or GPL/LGPL. SCOWL and VarCon carry a permissive notice-only licence.

## Options and rulings

| fork | options | ruling |
|---|---|---|
| 1 · build or wrap | wrap CSpell · port a Hunspell engine · codelaw's own | **codelaw's own** — wrapping breaks L11, the dictionaries mix in GPL/LGPL (L2), Hunspell engines are MPL/GPL |
| 2 · the known-typo list | ratify `typos`' list by name (A) · build codelaw's own from SCOWL (B) | **B** — *"Let's go with B."* |
| 3 · word sources | SCOWL and VarCon by name · other lists | **SCOWL and VarCon** — *"Approve both."* (D-42, D-43) |
| 4 · software jargon | ratify CSpell's MIT software-terms list · skip · write our own | **ratify** — *"Approve it."* (D-44) |
| 5 · where it ships | in the engine · a separate pack | **a separate pack** — *"want it as a separate package."* |
| 6 · defaults and the data's home | known-typo on, dictionary opt-in · both off; data in the pack · in the engine | **known-typo on, dictionary opt-in; data in the pack** — *"Go with the recommendation."* |

## Matrix

| | CSpell | typos | codelaw `spell` |
|---|---|---|---|
| approach | dictionary of right words | list of known typos | both: typo list (on) + dictionary (opt-in) |
| unattended fix | no | yes | yes, for the typo list |
| code licence | MIT | MIT/Apache | codelaw's own |
| data licence | mixed per dictionary | MIT/Apache, provenance open | SCOWL/VarCon notice-only, MIT software terms |
| reads the parse tree | no (regex ignores) | no | yes |
| reports a name once, where declared | no | no | yes |
| locale enforcement | partial | yes (VarCon) | yes (VarCon) |

## Consequences

- No third-party code: the engine side is codelaw's; the data is three ratified rows.
- The generated typo list starts smaller than `typos`' (about 96,000 entries, by one count) — the reopen-trigger watches that.
- Eighteen packs; L6, SR-RULE-PACKS and SR-PACKAGES change when W-103 lands.
