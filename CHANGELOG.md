# Changelog

Every user-visible change, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Each line names the work item it came from (`W-nn`); `python3 scripts/docs-sync.py --check` fails when an item `work/IMPLEMENTATION.md` dates after the last release is not named under *Unreleased*.

## Unreleased

### Added

- **A GitHub Action (W-97):** `uses: arpitarya/codelaw@v<version>` installs codelaw at that exact version (npm, or PyPI with `registry: pypi`), runs `codelaw check --format github` so findings annotate the pull request, passes the PR's base as `--changed-since`, and with `sarif: true` uploads SARIF to code scanning (the job needs `security-events: write`). It uses no other action. `working-directory` points it at a project in a subfolder; outputs `exit-code` and `sarif-file`. `codelaw init --ci github` (without `--autofix`) writes `.github/workflows/codelaw.yml` that uses it. See [USAGE](USAGE.md#without-ai-editor-pre-commit-ci).
- **Modern CSS and Sass parse without errors (W-62):** the CSS grammar reads `@import … supports(…)`, `@container name (…)`, `@custom-media`, `@font-feature-values`, `@page :first`, named-range keyframes (`entry 0%`), `.b &`, a custom property holding a block and `!ie`-style annotations; the SCSS grammar reads the Sass module system (`@use … as … with`, `@forward … show/hide/as`), maps, `!default`, `@if not`, rest and keyword arguments, `@include … using`, nested properties and interpolation in names and media features (Bootstrap's SCSS: 233 of 236 files parse cleanly, from 52). A fix that writes these forms is no longer refused, and `scss/at-if-no-null` now also fixes `@if $x == null` to `@if not $x`.
- **`--format agent` by itself inside a coding agent (W-96):** `codelaw check` and `codelaw fix` print the agent format with no flag when Claude Code (`CLAUDE_CODE_CHILD_SESSION`, or `CLAUDECODE` when the output is not a terminal), Codex (`CODEX_THREAD_ID`, `CODEX_SANDBOX`, `CODEX_SANDBOX_NETWORK_DISABLED`) or Gemini CLI (`GEMINI_CLI`) ran them. `--format` always wins; the new `CODELAW_FORMAT` sets the default for every run; `CI` alone never picks `agent`; `codelaw config --print` shows the `format` value and where it came from.
- **Which rules are ready to leave `preview` (W-100):** `python3 scripts/corpus.py promote` reports, per pack, which preview rules pass the promotion criterion on the pinned corpus — enough repositories and files, no false positive, fixes verified, one release in preview — and why each other rule is held; CI's corpus job writes it to its summary. No rule is promoted yet: the criterion's numbers wait on a ruling.
- **codelaw's rules, readable by an agent with nothing installed (W-98):** [`llms.txt`](llms.txt) at the repo root (the llmstxt.org index), [`docs/rules/llms-full.txt`](docs/rules/llms-full.txt) (every rule in one file: what it checks, its options, how to fix it, its examples) and [`docs/rules/rules.json`](docs/rules/rules.json), a catalogue of all 651 rules and the 23 engine rules — id, packs, languages, fix kind, options schema, presets, fix steps and a don't/do example. Generated from the rule files with `docs/rules/` and checked in CI.
- **The VS Code extension is packaged for the Marketplace and Open VSX (W-95):** CI builds and checks eight platform `.vsix` files of `codelaw.codelaw`, each with its platform's codelaw binary, and runs the extension's tests; the listing (icon, README, links) is ready. Not published yet: the publisher and tokens come first.
- **The Fux index packages follow fux-engine's latest release (W-91):** a daily `fux-bump.yml` job compares PyPI's fux-engine with the pinned `FUX_VERSION`, rebuilds and checks every index package with a newer one, and proposes the bump as one pull request (updated in place, never duplicated); each commit stays pinned, so the index bytes stay reproducible. Contributors only: nothing changes for a codelaw user.
- **Editor logs you can debug from (W-74):** the VS Code output channel is now one timestamped, levelled log: it opens with the extension, VS Code and OS versions, every binary it tried and why it chose one, and the server's version; `codelaw lsp` says which config and project each file got, when and why it reloads, and why a file shows nothing (no covered language, excluded, outside `include`, a config that does not load), once per file per reload; failures (a failed request, the server's exit code and last stderr, `client.start()` rejecting, *Explain rule* with no binary) are logged, not only popped up. New setting `codelaw.logLevel` (`error`, `warn`, `info`, `debug`; live, `debug` adds per-check timings and counts) and new command *codelaw: Copy debug info*. Source text and environment variables are never logged (SR-EDITOR decision 7).
- **Your own approved functions (W-73):** the five HTML-sink rules (`sec-js/no-dangerously-set-inner-html`, `no-unsanitized-html`, `no-jquery-html-sink`, `angularjs-sce-disabled`, `sec-ts/angular-native-element-html`) take a `sanitizers` option, a list of `"DOMPurify.sanitize"` (a global) or `{ name = "sanitizeHtml", module = "@acme/security" }`, matched by name and by where the name is imported from (named, aliased, default or namespace import; Python `from x import y`), with `sanitizers_mode = "extend"` (default, added to the built-in list) or `"replace"` (only yours count, so a direct `DOMPurify.sanitize` at the sink is reported). A rule option can now be a `call[]`, a rule can test it with `where: { $V: { not: { calls: sanitizers } } }`, and a message can name it with `$OPTION.sanitizers`. **New `js/use-instead` and `py/use-instead`** (in `js/recommended` and `py/recommended` at `warn`, inert until `replacements` is set): "use `apiFetch` instead of `fetch`", also as a prefix (`process.env` matches `process.env.API_URL`), never on a local shadow, exempt in the files `allow_in` names, and with `drop_in = true` an `auto` fix that swaps the call and adds the import once. Example config in USAGE.md. **`sec-ts/next-server-action-validation` and `sec-ts/no-unchecked-cast-of-input` take a `validators` option** the same way (`validators = [{ name = "checkInput", module = "@acme/validation" }]`, `validators_mode`), tested with the new `where: { $$MATCH: { not: { function_calls: validators } } }` — a call to one of them anywhere in the function or one around it; a `call[]` path segment may be `*<suffix>` (`"*Schema.parse"`).

- **Tests for new code (W-71):** opt in with `extends = ["codelaw:tests"]` (or a `[coverage]` table). `graph/untested-function` reports a new or edited JS, TS or Python function that no test file reaches by import (aliases, barrels and renamed re-exports followed; `mock.patch` strings do not count), and `graph/function-coverage` one whose lines in an lcov report are under `[coverage] min` (60) — `--coverage <path>` or `[coverage] report`, read by codelaw itself; `mode = "patch"`, `scope = "public"`, `require_report`, `on_no_change_set = "all"` and `ignore_names` tune it. Only the change set is judged: `--changed-since`, `--staged` or the agent hook's file; plain `check` prints `new code: no change set; test rules not evaluated`. `codelaw/stale-coverage` flags a report that no longer matches a file. **`.codelawignore`** exempts files (globs) and single functions (`path#Class.method`), each line with a reason and `expires=` or `forever`; an edit revokes an exemption (`on_touch=error|warn|keep`, `on_touch_scope=file|function`); `[coverage.ignore]` sets `require_expiry` and `require_on_touch`; `codelaw/incomplete-ignore` and `codelaw/stale-ignore` (removed by `codelaw fix`) report bad lines, and `codelaw exceptions` lists them. The MCP `check_paths` and `fix_paths` take `coverage`; JSON output has `new_code`. Also fixed: a renamed re-export (`export { a as b } from`) now counts as a use of `a` in the project graph, so `graph/no-unused-exports` no longer reports it.
- **`codelaw debug changed-functions` (W-71, step 1):** which functions a change set adds, edits or leaves alone, per file, for `--changed-since <ref>` or `--staged` (JS, TS, JSX, TSX and Python). A function is new when the base revision has none of that name, edited when its token stream differs (a reformat, a move or a comment outside it is not an edit) and untouched otherwise; `--format json` for tools. It is what the coming test-for-new-code rules will judge.
- **Every consumer-file text is a template (W-60):** what `codelaw init`, `init --git-hooks`, `init --agents`, `new-rule` and `init --ci` write comes from a file under `templates/` (L10), embedded in the binary, with a registry in `templates/README.md`; the output is byte-identical to before.
- **L11's dependency list and its check (W-65, W-66):** every dependency is a ratified row (L11); `cargo test --workspace` compares every manifest, lockfile and workflow against the ledger and names the offender. The 32 units were ruled: 29 ratified, `strsim`, `anyhow` and `postcard` to be removed (W-67).
- **CSS Modules, in the `css` pack and a new `css-modules` pack (npm only)**: a stylesheet is a module when it is named `*.module.css` or `*.module.scss`, or matches `[css] modules`; `[css] modules_convention` is css-loader's `localsConvention` (`asIs` by default). The `css/*` rules read modules without reporting their syntax (`:global`, `:local`, `composes:`, `:export {}`, `:import() {}`, `@value`). The project graph joins a module's classes with the JavaScript and TypeScript that read them — `styles.x`, `styles["x"]`, `const { x } = styles`, `import { x }` — and five rules use it: `css-modules/no-unused-class` (reported in the stylesheet; `fix --unsafe` deletes the rule), `no-undefined-class` (reported in the JS or TS file, at the name), `composes-valid` (a missing file or class, or `composes` in a nested or non-class rule), `class-naming` (`camelCase`, `kebab` or `any`) and `no-global`, with `css-modules/recommended` and `css-modules/strict`. **Never a false positive on dynamic access**: a module read by `styles[name]`, spread, rest-destructured or passed to a function is silent, and so is a module no file imports. Seventeen packs: fifteen on npm, ten on PyPI (L6, the decider's ruling of 2026-10-26); `codelaw init` adds the pack for `*.module.*` files. `scss`'s `.module.scss` works the same (W-63).
- **SCSS (`.scss`) is a CSS dialect**, as JSX is a JavaScript one (L3 amended, the decider's ruling of 2026-10-26): `codelaw check` and `codelaw format` read it with tree-sitter-scss 1.0.0 (vendored, B-047: "own grammar") and Biome's SCSS formatter; the `css/*` rules of `@codelaw/rules-css` run on it — `//` comments, `$variables`, nesting with `&-suffix`, `@mixin`/`@include`/`@use`/`@if` and the rest of Sass's at-rules, `#{}` interpolation and nested properties are read, not reported (64 of the 71 `css` rules declare `scss`; the `@import`, `//`-comment, range-media and at-rule-no-unknown rules stay CSS-only, `graph/no-unused-css-classes` does not read SCSS yet, and the new `css/max-lines` counts `.scss` files too). **A new pack, `scss`** (`@codelaw/rules-scss` on npm, `codelaw-rules-scss` on PyPI — sixteen packs now, fourteen on npm and ten on PyPI) holds 15 `scss/*` rules, ported from stylelint-scss and from Dart Sass's deprecations: `no-import`, `no-global-function-names` (renames to `map.get()` and the like, adding each `@use "sass:…"` once), `no-slash-division` (`math.div`), `at-rule-no-unknown`, `function-no-unknown`, `no-duplicate-dollar-variables`, `no-duplicate-mixins`, `dollar-variable-pattern`, `at-mixin-pattern`, `percent-placeholder-pattern`, `at-extend-no-missing-placeholder`, `load-no-partial-leading-underscore`, `at-if-no-null`, `double-slash-comment-empty` and `max-nesting-depth`, with `scss/recommended` and `scss/strict`. `codelaw init` adds the `scss` and `css` packs for `.scss` files or `sass` in `package.json`; the VS Code extension and the config schema know `scss`. Not yet: tree-sitter-scss 1.0.0 reads some modern Sass as `ERROR` (`@if not …`), so the `css/*` rules still read the text, and the graph does not read `.scss` classes (W-62).
- **Size limits for JavaScript, TypeScript and Python:** `js/max-lines` and `py/max-lines` (lines per file, 300 / 1000), `js/max-lines-per-function` and `py/max-lines-per-function` (50) and `js/max-params` and `py/max-params` (3 / 5), each with options for what counts (`skip_blank_lines`, `skip_comments`, `skip_docstrings`, `skip_imports`, `include_nested`, `include_iife`, `ignore_names`, `max_positional`, `count_this`, `count_varargs`, `ignore_self_cls`, `ignore_overrides`, `ignore_declarations`, `ignore_constructor_injection`). All six are `manual` fixes, in the opt-in presets `js/size` and `py/size`. A finding can now carry structured data, and these carry the measured value and the limit: `--format json` has `"data": { "lines": 412, "max": 300 }` on the diagnostic and SARIF has it under `properties.data`. A rule page's example or case fence takes `options=<json>` (`js options={"max":3}`), so a threshold rule's Don't can fire (W-58).
- **`security-ts`: 16 security rules for TypeScript, TSX and the frameworks that use them (W-55).** `sec-ts/no-unchecked-cast-of-input`, `no-ts-ignore-on-sink`, `no-any-request-handler`, `no-permissive-schema` (`.passthrough()` to `.strict()`), Angular (`angular-bypass-security-trust`, `angular-native-element-html`), NestJS (`nest-validation-whitelist`, `nest-cors`, `nest-missing-guard`, `nest-throttler`), Next.js server actions, tRPC, and raw queries in Prisma, TypeORM, Drizzle, Kysely and MikroORM, each with a CWE, an OWASP Top 10:2025 category and Do/Don't examples in TypeScript and TSX. `sec-ts/recommended` extends `sec-js/recommended` and adds 10 at `error`; `sec-ts/strict` adds 6 more at `warn`. They read syntax, not types, and each page says what it cannot see.
- **`security-js`: 66 security rules for JavaScript, JSX, TypeScript and TSX (W-54).** Injection (`sec-js/no-eval`, `no-child-process-shell`, `no-sql-template`, `no-nosql-injection`, `no-ssti`, `no-xxe`, `no-prototype-pollution` …), cross-site scripting and the browser (`no-unsanitized-html`, `no-dangerously-set-inner-html`, `postmessage-origin`, `no-bidi-characters` …), traversal, SSRF and redirects, TLS, CORS, cookies, sessions and Express, GraphQL and Electron settings, weak crypto, hard-coded secrets, JWT checks, and model output or request data reaching a prompt or a sink. Each rule has a CWE, an OWASP Top 10:2025 category, a fix class (17 `suggest`, 49 `manual`) and Do/Don't examples in all four languages; `sec-js/recommended` turns on 55 at `error`, `sec-js/strict` 11 more at `warn`. Request-source rules read `data/sources/` and say they are not taint analysis. The README's table covers every eslint-plugin-security rule: ported, widened or not ported, and why.
- **`[scope.<name>]` replaces `[[overrides]]`, and `[profile.<name>]` replaces `[profiles.<name>]`:** a named group of files — `files`, `exclude`, `rules`, `remap` — with its own rule settings, applied after `[rules]` in the order written (`[scope.utils]` with `files = ["**/*.utils.ts", …]` and `max = 50`). A preset ships scopes (`js/recommended`: `tests`, `stories`, `config`; `py/recommended`: `tests`) and a project scope of the same name extends it, keeping the preset's `files`. A scope name is `[a-z0-9_-]+` and `default` is reserved. `codelaw config --scopes` lists every scope with its files and source, and `config --print` names the scope each value came from. **`[[overrides]]` (loaded as `scope.override-<n>`) and `[profiles.<name>]` still load, each with one warning, and are removed in the next minor release** (SR-CONFIG decision 3a, W-59).
- **The post-commit hook reminds you what you owe:** after each commit it lists your own exceptions that expire within 7 days and the baseline's 30-day burn-down as one line, and stays silent when there is nothing to say; re-run `codelaw init --git-hooks` to update an installed hook (W-50).
- **`css/max-lines` and `html/max-lines`:** a line limit per stylesheet (300) and per page (400), with `max`, `skip_blank_lines`, `skip_comments`, `skip_imports` (CSS: `@import`, `@use`, `@forward`) and `skip_embedded` (HTML: the lines inside `<script>` and `<style>`); SCSS `//` comments are skipped in `.scss` files. Opt in with `codelaw:css/size` and `codelaw:html/size`; the fix is manual, a split. A `<style>` in a page is part of the page, never a file (W-61).
- **An optional Fux index package beside each rule pack:** `@codelaw/rules-<name>-fux-index` on npm (ten) and `codelaw-rules-<name>-fux-index` on PyPI (six), each a Fux index of that pack's rules, data only and never installed by default — add one when your repository uses Fux and `fux_search` finds the rules from plain words. `codelaw init` installs none; in a repo with a `.fux/` folder it prints the install and pin lines. Built in CI by a pinned fux, twice, to the same bytes; not published yet (L6 decision 12, W-34).
- **A scheduled auto-fix PR:** `codelaw init --ci github --autofix weekly` (or `gitlab`, `daily`) writes a workflow that runs the safe fixes, the formatter and `baseline prune` on a schedule and keeps one pull request open from `codelaw/autofix`, its body listing the fixes per rule and file and the week's burn-down; `--unsafe` puts the `suggest` fixes in a second PR. The text comes from `templates/ci/` (SR-CLI-MCP decision 12, W-51).
- **CI report formats:** `--format github|gitlab|junit|checkstyle` on `check`, `fix` and `format --check`. `github` prints workflow commands (`::error` / `::warning` / `::notice`) so findings annotate the PR diff with no SARIF upload; `gitlab` is Code Quality JSON; `junit` and `checkstyle` are XML. Every format carries the fix class and steps, and fingerprints are a BLAKE3 hash of rule, file, message and occurrence index, never the line, so moving code does not re-open a finding. Output is byte-identical for the same input and exit codes are unchanged (SR-CLI-MCP decision 4, W-45).
- **`codelaw baseline history`:** `--since`, `--by commit|day|week`, `--rule`, `--format text|json|csv|markdown`, read from git with no re-lint, so the baseline's burn-down over commits is a command (SR-BASELINE decision 10, W-47).
- **What is excepted and what expires:** `codelaw exceptions` lists every baseline entry, deprecation and inline `codelaw-ignore` once, with `expires`, days left on the as-of date, `added_by`, reason and uses. `--expiring 30d`, `--expired`, `--mine`, `--rule` and `--path` filter; `--group-by added_by|rule|file|expires-month` groups; `--format text|json|csv|markdown` gives a table for a stand-up or a PR comment; `--fail-if-expiring 7d` exits 1 for a scheduled job. The MCP tool `list_exceptions` returns the same JSON (SR-BASELINE decision 11, W-46).
- **Git hooks in one command:** `codelaw init --git-hooks [pre-commit,post-commit]` writes a blocking `pre-commit` (fixes the fully staged files and re-stages them, checks every staged file, never fixes a partly staged one) and a post-commit that always exits 0, chains any hook already there and never overwrites one. `.pre-commit-hooks.yaml` ships hooks `codelaw-check` and `codelaw-fix` for the pre-commit framework, and USAGE has husky and lefthook recipes (SR-CLI-MCP decision 11, W-50).
- **Dependencies behind their latest version, highlighted:** `codelaw deps refresh` reads npm and the Python index (a private npm registry and token from `.npmrc`, a private index from `PIP_INDEX_URL` or `[[tool.uv.index]]`) and writes `.codelaw/deps-snapshot.json`, sorted so a refresh with nothing new writes the same bytes — the only command that uses the network (L5 decision 3, amended). `data/outdated-dependency` reads it offline on every `package.json` and `pyproject.toml`: a major version behind is `warn`, minor and patch `info`, a deprecated (npm) or yanked (PyPI) version in use `error`, a lockfile behind a range that allows the latest `info`; its `suggest` fix moves the range and keeps `^`, `~`, `>=` or `==`. `data/stale-deps-snapshot` reports a snapshot older than `[deps] max_snapshot_age` on the as-of date. `[deps]` sets each kind's severity, `min_release_age`, `prerelease` and `ignore`. Both rules are in `data/package-json` and `data/pyproject` (W-52).
- **`security-html`: 19 HTML security rules** (W-56): `sec-html/no-inline-event-handler`, `no-javascript-url`, `no-mixed-content`, `password-form-post`, `iframe-sandbox`, `csp-meta-unsafe`, `no-credentials-in-url`, `no-template-html-sink`, `referrer-policy`, `no-srcdoc-script`, `sri-crossorigin`, `no-secret-in-hidden-input`, `angularjs-url-expression`, `no-unsafe-template-interpolation` in `sec-html/recommended` (with the html pack's five security rules); `no-external-base`, `no-plugin-embed`, `no-sensitive-comments` (`auto`), `form-csrf-token` and `iframe-allow-powerful` in `sec-html/strict`. Each names its CWE and OWASP 2025 category.
- **Four security packs, as scaffolds:** `security-js` (npm and PyPI), `security-ts` (npm), `security-html` (npm and PyPI) and `security-python` (PyPI), each with `recommended` and `strict` presets and no rules yet — their catalogues are W-54 to W-57. Fifteen packs: thirteen on npm, nine on PyPI (L6, the decider's ruling of 2026-10-25). **A rule can carry `security: { cwe, owasp, severity }`**: its finding names the CWE (`(CWE-79)`), `codelaw rules --tag cwe:79` / `--tag owasp:A05` select by it, `codelaw rules --security-coverage` prints the OWASP Top 10:2025 × rule matrix, and SARIF carries `security` and `external/cwe/cwe-<n>` tags and a `security-severity`. **A `from_source:` predicate** matches a sink argument that is, or is bound in the same function to, a request source such as `req.query` or `request.args` — not taint analysis. **A preset can extend another first-party preset**: `sec-ts/*` extends `sec-js/*`, and `sec-html/recommended` turns on the html pack's new `html/security` preset instead of copying its rules. `codelaw test` on a pack folder with no rules passes (W-53).
- **`security-python`: 61 Python security rules** (`sec-py/*`, PyPI only), each mapped to CWE and OWASP Top 10:2025 and carrying a fix: Bandit's and Ruff `S`'s checks (exec and eval, shell, SQL, deserialisation, YAML, XML, TLS, hashes, random, secrets, temp files, tar, Jinja2, Mako, `mark_safe`, paramiko, key sizes, ciphers), Django, Flask and FastAPI settings and sinks (open redirect, path traversal, SSRF, mass assignment, uploads, cookies, CORS, reflected XSS), ML model loading (`torch.load`, `joblib`, `numpy`, Hugging Face pins, `trust_remote_code`) and language-model prompt and output rules. `sec-py/recommended` is 57 rules at `error`, `sec-py/strict` adds 4 at `warn`; the README accounts for every Bandit check (W-57).
- **Dev-server plugins:** `@codelaw/vite-plugin` (errors in Vite's overlay, warnings in the terminal), `@codelaw/webpack-plugin` (errors and warnings in webpack and, unchanged, Rspack) and `@codelaw/next` (`withCodelaw(nextConfig)`; under Turbopack the findings print to the terminal beside `next dev`). They run `codelaw check --watch` on the `local` profile while you work and one `check --profile ci` on a build, which fails on an error (`failOnError`); none lints itself or has a dependency, and stopping the dev server stops the watcher (W-49). Their example apps on the real hosts are filed as W-70.
- **Watch mode:** `codelaw check --watch` checks once, then again on every save — the saved file, the files whose rules read it, and the project rules over the whole graph, so deleting the last use of an export reports it in the file that exports it — until Ctrl-C, which exits 0. A change to `codelaw.toml`, a rule, the baseline, an `.editorconfig` or an ignore file reloads the project. Text clears the screen and ends with a `watching … · run N · … changed` line; `--format json` prints one object per run on one line, with a `watch` field. It runs the `local` profile by default and in its own process on every platform, Windows included; `fix --watch` fixes each saved file and skips its own writes (W-44).
- **Six TanStack Query rules from TanStack Query v5's own guides**, each where a guide states a rule a matcher can decide without types: `tanstack-query/no-renamed-v4-options` (`cacheTime` → `gcTime`, `useErrorBoundary` → `throwOnError`, fixed automatically), `no-removed-v4-options` (query `onSuccess` / `onError` / `onSettled`, `keepPreviousData`, `isDataEqual`, `context`), `object-syntax` (v4's positional `useQuery(key, fn, options)` and QueryClient calls, with a suggested rewrite), `array-query-key`, `no-mutating-set-query-data` and `no-unsupported-suspense-options` (`enabled`, `placeholderData`, `throwOnError` on a suspense query). All six are in `tanstack-query/recommended` (13 rules), and the pack now has a pinned corpus: `full-stack-fastapi-template`, `bulletproof-react` and TanStack Query's own repository (W-42).
- **Exceptions with an expiry date, a reason and an author:** a baseline entry, a deprecation and an inline `codelaw-ignore` take `expires` (the first day it no longer holds), `warn_days` and `added_by` (`by=` inline). From `warn_days` before the date (3 by default) the exception is a warning, `codelaw/expiring-exception`; on the day it is an error, `codelaw/expired-exception`, and its findings come back at their own severity. `[exceptions] require_expiry = true` makes the date mandatory (`codelaw/exception-without-expiry`); `added_by` is checked against git under `--staged` and `--changed-since` (`codelaw/exception-author`). `baseline add` and `deprecate` take `--expires`, `--warn-days` and `--added-by` (default `git config user.email`). `until` still works for one minor release, read as `expires` the day after; messages now say "expires 2027-04-01" where they said "deadline 2027-03-31" (SR-BASELINE decision 9, W-40).
- **`react/recommended` gains ten React hooks rules**, from eslint-plugin-react-hooks 7.1.1's React Compiler rules and @eslint-react 5.28.8, each decided from one file's syntax: `react/no-set-state-in-render`, `react/no-set-state-in-effect`, `react/no-ref-in-render` (`ref.current` during render, the `if (ref.current === null)` initialisation allowed), `react/purity` (`Math.random()`, `Date.now()`, `new Date()` … during render), `react/no-nested-components`, `react/use-memo` (an async, parameterised or value-less `useMemo` callback, or an unused result), `react/globals` (a module-level or global value changed during render) and `react/error-boundaries` (`try`/`catch` around returned JSX or `use(…)`) at `error`; `react/no-unnecessary-use-prefix` and `react/prefer-lazy-state-init` (`useState(compute())` → `useState(() => compute())`, a `suggest` fix) at `warn`. The preset now holds 29 rules (W-43).
- **`react/no-context`**: no `createContext` or `useContext` from `react` — named, aliased, or `React.*` — and the recipe to adopt it in a codebase that already uses context: `codelaw baseline add --rule react/no-context --warn-from <today> --on-touch keep` keeps today's uses as warnings while a new use, in a new file or an old one, fails. A team's choice, so in no preset; `codelaw explain react/no-context` shows the recipe (W-41).
- **Warn on a laptop, fail in CI:** `[profile.<name>]` (first written `[profiles.<name>]`) holds `rules` and `scope`s laid over the config. codelaw runs the `ci` profile when `CI` is set (not `false` or `0`), `local` otherwise; `--profile <name>` or `CODELAW_PROFILE` picks one. `codelaw hook` and the MCP server run `ci`, so an agent gets CI's verdict; the editor runs `local`. Reports name the profile in use (`profile ci (CI=true)`; `profile` in JSON; `config --print`) (W-39).
- **`remap` on a scope (first an `[[overrides]]` entry):** maps each severity in a glob to another or to `off` — `{ error = "warn" }` never fails the run, `{ warn = "error" }` admits no warnings — applied last, after the baseline, never to `codelaw/*` diagnostics (W-39).
- **`js/no-console`:** calls on the global `console`, with an `allow` option and a `suggest` fix that deletes the statement; in `js/recommended` at `warn` (W-39).

### Fixed

- **`scripts/npm-trust.sh` no longer stops at a package npm already trusts (W-85):** an E409 (*"a trusted publisher configuration … already exists"*) counts as trusted; any other failure is listed at the end with exit 1, and `--fux-index` adds the fifteen Fux index packages. RELEASING.md's *Every release* now starts by re-checking trust that npm let lapse.
- **CI on `main` is green again (W-84):** every `ci.yml` job passes (run 40437239647); the commit guard's replay starts after the last pushed commit that skipped its record, and the release smoke runs on Alpine's BusyBox `diff` and compares Windows' `--prefer-warm` with a fresh check.
- **CSS and SCSS read the same on Windows, Linux and macOS (W-44):** the grammars' scanners asked the C library what a space is, and Windows' answer includes U+00A0, so on Windows `.menu<U+00A0>.item` in a `.scss` file read as two classes and `css/no-irregular-whitespace` could not see the no-break space (musl builds differed the same way on U+2028 and U+3000). A team that uses no agent files installs nothing more.

Add your own to `sanitizers`. The rules are `stability: preview`.

A bare `validate(x)` the file does not import, or a local `validate` made by `ajv.compile`, now leaves the cast or the server action reported; zod, valibot, yup, joi, class-validator, class-transformer's `plainToInstance`, superstruct and typia imports still pass, and so do a `*Schema.parse`, `.safeParse`, `.parseAsync`, `.validate` and `.assert` on any value. Add your own to `validators`. The rules are `stability: preview`.
- **Three fewer dependencies:** "did you mean …?" suggestions use codelaw's own `levenshtein` and `jaro_winkler` (same results), the cache writes its own binary format instead of `postcard` (old cache files are ignored and rebuilt; a truncated or corrupt one is a miss), and the unused `anyhow` line is gone from `codelaw-format` (L11, W-67).

## 0.1.0 — 2026-10-24, preview, on npm only

The first release: the engine and the five rule packs of that layout, published to npm by hand from CI's build of `5e489f4` (W-29). Nothing is on PyPI yet.

### Added

- **The engine:** one Rust binary covering JavaScript, JSX, TypeScript, TSX, Python, JSON, YAML, TOML, Markdown, CSS and HTML, alone or in any combination.
- **Commands:** `check`, `fix` (with `--unsafe` and `--dry-run`), `test`, `rules` (`--for`, `lint`), `explain`, `tree`, `new-rule`, `init` and `cache`.
- **Output formats:** `text`, `json` and `agent`.
- **Rules as Markdown files:** front matter, a `codelaw` matcher and fix block, and `Do` / `Don't` examples that double as tests.
- **Fix classes:** `auto`, `suggest` and `manual`. Fixes run in passes until nothing more changes, and a fix that would add a syntax error is rolled back.
- **Five rule packs, 419 rules, all `preview`:**
  - `js`: 140 rules, from ESLint, typescript-eslint, eslint-plugin-react, react-hooks, eslint-plugin-n and @stencil/eslint-plugin.
  - `python`: 99 rules, from Ruff's defaults, flake8-bugbear, isort and `RUF022`.
  - `html`: 72 rules, from html-validate.
  - `css`: 71 rules, from stylelint's recommended and standard configs.
  - `data`: 37 rules, JSON/YAML/TOML correctness and markdownlint.
- **Configuration:** `codelaw.toml`, `[tool.codelaw]` in `pyproject.toml`, or `"codelaw"` in `package.json`, with strict validation, `[rules]` and `[[overrides]]`.
- **Local rules** in `.codelaw/rules/`, picked up with no build step.
- **Licence: MIT**, for the repo and every package. `LICENSE` at the root and in each rule pack.
- `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` and the GitHub issue and pull-request templates (W-06).
- **The formatter:** `codelaw format [--check] [--diff]` for all nine languages, with six engines compiled in: Biome, Ruff's formatter, pretty_yaml, taplo, dprint-plugin-markdown and markup_fmt. `fix` ends with a format. `check` reports unformatted files as `format/unformatted` (`auto`). A format that would not parse, would change again on a second run, or would change a JSON/YAML/TOML value is refused and reported as `format/failed`. Line endings are kept unless `[format] end_of_line` is set (W-07).
  - `.editorconfig` is read under `[format]`; `codelaw format --import-config` turns a Prettier, Ruff or Black config into `[format]`; `codelaw-format-ignore` and `prettier-ignore` markers are honoured by every engine (W-23).
- **`codelaw mcp`**, the MCP server for agents (W-08), and **`codelaw lsp`**, the language server: diagnostics, quick fixes, fix all, hovers, document and range formatting; closed files' trees kept in a bounded cache, `[lsp] tree_cache` (W-09, W-15).
- **Agents:** `codelaw hook` checks and fixes the files an agent just edited and returns what is left; `codelaw init --agents` installs the hooks and writes each agent's files; `codelaw sync-agents [--check]` rewrites them from the rules and skills (W-10).
- **Project-wide rules** on a whole-repo graph: `graph/no-unused-exports` (JS, TS, Python), `graph/no-unused-css-classes`, and the six `node/no-{missing,extraneous,unpublished}-{import,require}` rules; `codelaw graph refs` and `graph why-unused` (W-11).
- **Rules on JSON, YAML and TOML paths:** `target:` + `assert:` rules, `schema:`, and the `sort-keys`, `ensure-key` and `when` fixes (W-12).
- **Baselines and deprecations:** `codelaw baseline add|prune|check` grandfathers a rule's existing findings per file, with a deadline (`until`), a touch policy (`on_touch`) and a ratchet that lets counts only go down; `codelaw deprecate` and `.codelaw/deprecations.toml` drive the engine's own `graph/no-deprecated-usage`. Deadlines are judged on `HEAD`'s commit date or `--as-of`, never the clock; `--changed-since <ref>` and `--staged` say which files count as touched (W-13).
- **Adapters:** `check` and `fix` also run the installed oxlint, Ruff, stylelint and html-validate and merge their findings; `--no-adapters` turns them off (W-14).
- **Warm processes:** `codelaw daemon start|stop|status`, warm sockets for `lsp` and `mcp`, and `--prefer-warm`; a compiled rule-set cache (W-15).
- **Debugging and output:** `codelaw config --print|--schema`, `codelaw match --explain`, `fix --trace`, `--timings`, `--format sarif`, `format --format json`; the npm and Python APIs gain `format` and `rulesFor` / `rules_for` (W-16).
- **`codelaw bench`** times every performance-budgeted operation on a generated 10,000-file workload and compares it with `perf/budgets.toml` (W-19); it builds on Windows (W-24).
- **Rules added since the packs were first built:** `md/relative-links`, `html/no-utf8-bom` and `node/hashbang`, which read the files around them; `css`/`html` tagged templates in JS and TS are checked as CSS and HTML (W-21).
